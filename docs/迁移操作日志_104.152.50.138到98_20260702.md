## 4. 问题清单与修复（重点）

### 4.1 lightmes 启动缺包

**症状**：`ModuleNotFoundError: No module named 'oss2'`

**根因**：远端 lightmes 用了多云存储（阿里云 OSS / 七牛 / 腾讯云 COS），但 requirements.txt 没列出来。

**修复**：
```bash
/www/server/pyporject_evn/lightmes/bin/pip install oss2 qiniu cos-python-sdk-v5
```

**教训**：多云 SDK 是约定式依赖，迁移时必须主动补齐（已写入 `common_pitfalls` 记忆）。

---

### 4.2 lightmes celery 启动路径错误

**症状**：worker 报 `ModuleNotFoundError: No module named 'app'`

**根因**：用 `cd && nohup &` 时，bash 子 shell 不继承 cd 目录。

**修复**：在 `nohup` 前显式 `cd /www/wwwroot/lightmes/backend`：
```bash
cd /www/wwwroot/lightmes/backend && for i in 1 2 3 4 5; do
  nohup /www/server/pyporject_evn/lightmes/bin/celery -A app.celery_app worker \
    -l info --concurrency=4 -Q celery,default,ai -n lightmes@%h \
    >> /www/wwwlogs/python/lightmes/celery_worker${i}.log 2>&1 &
done
```

---

### 4.3 openai 数据库权限

**症状**：`permission denied for table catalog_model_category`

**修复**：给 `openai` 用户授权：
```sql
GRANT ALL PRIVILEGES ON DATABASE openai TO openai;
GRANT ALL ON ALL TABLES IN SCHEMA public TO openai;
```

### 4.4 openai redis 版本过低

**症状**：`Health check failed: 'Redis' object has no attribute 'aclose'`

**根因**：`redis.aclose()` 是 redis-py 5.0+ 才有的方法。

**修复**：
```bash
/www/server/pyporject_evn/openai/bin/pip install --upgrade redis
```

### 4.5 labors 项目（最复杂，遇到 6 个问题）

#### 4.5.1 bcrypt 5.0.0 与 passlib 不兼容

**症状**：cenkor-admin 登录验证密码时静默崩溃（前端只看到"账号密码错误"）。

**根因**：`bcrypt==5.0.0` 移除了 `__about__` 属性，passlib 检测版本时抛 `AttributeError`。

**修复**：
```bash
/www/server/pyporject_evn/cenkor/bin/pip install 'bcrypt<5'
# 降级到 bcrypt 4.3.0
```

**教训**：在 Python 3.13 + 较新 pip 环境中，`pip install bcrypt` 会拉到 5.x，但 passlib 1.7.x 还停留在 4.x 时代。**所有基于 passlib 的项目必须锁定 `bcrypt<5`**（已写入 `common_pitfalls` 记忆）。

#### 4.5.2 SQLAlchemy 2.0.25 + Python 3.13 TypingOnly 报错

**症状**：`AssertionError: Class SQLCoreOperations directly inherits TypingOnly`

**修复**：
```bash
/www/server/pyporject_evn/labors/bin/pip install --upgrade 'sqlalchemy>=2.0.31'
```

#### 4.5.3 缺 asyncpg 驱动

**症状**：`ModuleNotFoundError: No module named 'asyncpg'`

**修复**：
```bash
/www/server/pyporject_evn/labors/bin/pip install asyncpg
```

#### 4.5.4 requirements.txt 版本过旧 + C 扩展编译失败

**症状**：`pip install -r requirements.txt` 报 `Failed building wheel for pydantic-core / asyncpg`

**根因**：requirements.txt 里 `sqlalchemy==2.0.25 / pydantic==2.5.3 / asyncpg==0.29.0` 等旧版本，在 Python 3.13 下编译失败。

**修复**：放弃 `pip install -r`，改为逐个装新版（不锁版本）：
```bash
pip install sqlalchemy pydantic asyncpg redis pydantic-settings
```

#### 4.5.5 ImportError: EmployeeUser

**症状**：`ImportError: cannot import name 'EmployeeUser' from 'app.models.employee'`

**根因**：`leader.py` 第 12 行写错：
```python
# 错的：
from app.models.employee import Employee, EmployeeUser
# EmployeeUser 不在 employee.py，在 employee_user.py
```

**修复**：拆成两行：
```python
from app.models.employee import Employee
from app.models.employee_user import EmployeeUser  # 已存在于第 18 行
```

#### 4.5.6 缺 app.models.employee_pricing

**症状**：`ModuleNotFoundError: No module named 'app.models.employee_pricing'`

**根因**：`leader.py` 引用 `EmployeePricing`，但模型文件根本没建。远程能跑是因为用了旧的 `.pyc` 缓存。

**修复**：新建 `/www/wwwroot/labor/backend/app/models/employee_pricing.py`，提供最小 stub：
```python
class EmployeePricing(TimestampMixin, SoftDeleteMixin, Base):
    __tablename__ = "employee_pricings"
    id: Mapped[int] = mapped_column(primary_key=True)
    employee_id: Mapped[int] = mapped_column(Integer, ForeignKey("employees.id", ondelete="CASCADE"))
    pricing_item_id: Mapped[int] = mapped_column(Integer, ForeignKey("pricing_items.id", ondelete="CASCADE"))
```

### 4.7 api (workflow-api) 三连坑

#### 4.7.1 缺前端 nginx 反代配置

**症状**：`https://api.user.023ent.net/login` 页面白屏。

**根因**：本地 nginx 配置用了 `root /www/wwwroot/api/dist` 直接服务静态文件，缺少 `/api` 反代到 5000 后端。

**修复**：同步远程 nginx 配置 + 改用宝塔 Vite 5173 反代：
```nginx
location / {
    proxy_pass http://127.0.0.1:5173;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection 'upgrade';
    ...
}
```

#### 4.7.2 node 命令不在 PATH

**症状**：`Exit 127 / command not found` 启动 `node dist-api/server.js` 失败。

**根因**：宝塔 Node 安装在 `/www/server/nodejs/v24.16.0/bin/`，但 PATH 没加。

**修复**：用全路径启动：
```bash
nohup /www/server/nodejs/v24.16.0/bin/node /www/wwwroot/api/dist-api/server.js
```

#### 4.7.3 手动 nohup 不够稳定 → 改用 Docker

**用户反馈**："你这怎么启动的啊？应该程序启动就应该启动啊"

**修复**：用 `docker compose` 启动 `workflow-api` 容器（Dockerfile 已写好，自动 restart=unless-stopped）：
```bash
cd /www/wwwroot/api && docker compose up -d
```

## 7. lightmes celery 自愈机制（已配置）

### 7.1 双保险机制

| 触发 | 作用 | 配置位置 |
|---|---|---|
| `@reboot` | 服务器重启后等待 8 秒再启动 celery | 系统 crontab（root） |
| `*/5 * * * *` | 每 5 分钟检测，进程死了自动拉起 | 宝塔计划任务 / 系统 crontab |

### 7.2 已创建的脚本

| 路径 | 用途 |
|---|---|
| `/www/server/cron/lightmes_celery_start.sh` | @reboot 用，先 sleep 8 |
| `/www/server/cron/lightmes_celery_watchdog.sh` | 5 分钟保活用 |
| `/www/wwwroot/lightmes/scripts/start-celery.sh` | 幂等启动（远程同步，已存在） |

### 7.3 计划任务配置（用户自行在宝塔界面添加）

- 任务 1："lightmes开机启动celery"
  - 类型：Shell 脚本
  - 周期：每 1 分钟（界面没有 @reboot 选项）
  - 脚本：
    ```bash
    #!/bin/bash
    sleep 8
    /bin/bash -lc '/www/wwwroot/lightmes/scripts/start-celery.sh >> /tmp/lightmes-celery/boot.log 2>&1'
    ```

- 任务 2："lightmes celery 自愈"
  - 类型：Shell 脚本
  - 周期：每 5 分钟
  - 脚本：
    ```bash
    #!/bin/bash
    /bin/bash -lc '/www/wwwroot/lightmes/scripts/start-celery.sh >> /tmp/lightmes-celery/boot.log 2>&1'
    ```
