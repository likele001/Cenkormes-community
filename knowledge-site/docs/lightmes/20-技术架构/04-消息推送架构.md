# 消息推送架构

支持多渠道，均通过「渠道回调入口 + push_log 落库 + 定时重试/预警」体系。

## 渠道
| 渠道 | 回调路由 | 推送日志表 | 配置入口 |
|------|---------|-----------|---------|
| 飞书 | /feishu | feishu_push_logs | /admin/system/feishu |
| 企业微信 | /wecom | wecom_push_logs | /admin/system/wecom |
| 钉钉 | /dingtalk | dingtalk_push_logs | /admin/system/dingtalk |
| 公众号 | （推送） | wechat_mp_push_logs | /admin/system/wechat_mp |
| 小程序订阅 | /miniapp | user_wechat_subscriptions | — |

## 核心机制
- **推送服务**：services/feishu、wecom、dingtalk、wechat_mp
- **落库可追溯**：每次推送写对应 push_log，便于排查与统计
- **重试/预警**：push_retry_alert（0053 定时任务）+ Celery 定时轮询失败重发
- **开放回调安全**：Webhook 若配置 secret，用 `x-webhook-secret` 头或 `?secret=` 参数校验，`timingSafeEqual` 常量时间比较防时序攻击
- **工厂日报/消息中心聚合**：admin/system/message_center + notification 表

## 新增渠道步骤
1. 新建 `api/<channel>/router.py` 回调 + `models/<channel>_push_log.py`
2. `router.py` include_router 注册回调
3. 建迁移（幂等建 push_log 表）
4. 前端 system 下加渠道配置页

## 注意事项
- 勿直接对接微信企微/飞书/钉钉原生复杂 API（签名/限流/平台差异），统一走用户提供的 Webhook 或既定入口
- 改造渠道时移除无关渠道，仅保留需要运营的渠道
